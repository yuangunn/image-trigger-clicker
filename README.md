# image-trigger-clicker (`itc`)

화면에 지정한 이미지가 나타나면, 미리 설정해 둔 좌표를 클릭하는 macOS용 범용 데스크톱 자동화 CLI.

**핵심 설계: 이미지는 "언제 누를지"만 판단하는 트리거다. "어디를 누를지"는 따로 지정한다.**

대부분의 이미지 매칭 도구는 찾은 이미지의 중앙을 누른다. 이 도구는 그것을 기본값으로 두지 않는다.
"저 아이콘이 보이면, 화면 아래쪽 저 버튼을 눌러라" 같은 동작이 실제로 필요한 형태이기 때문이다.

쓰임새 예시:

- **접근성 보조** — 반복해서 나타나는 확인 대화상자를 대신 처리
- **반복 UI 작업** — 긴 배치 작업 중 주기적으로 뜨는 진행 확인창 처리
- **테스트 자동화** — 자동화 API가 없는 GUI 앱의 상태를 화면으로 판정하고 조작

## 설치

### Homebrew (권장)

```bash
brew tap yuangunn/tap
brew install image-trigger-clicker
itc doctor          # 설치 직후 반드시 실행해서 권한 상태를 확인한다
```

`brew tap yuangunn/tap` 은 `github.com/yuangunn/homebrew-tap` 저장소를 가리킨다.
(Homebrew 규칙상 tap 저장소 이름은 반드시 `homebrew-` 로 시작해야 한다.)

설치가 끝나면 **반드시 `itc doctor`** 를 실행하라. 권한이 없으면 오류 없이 조용히
아무것도 매칭되지 않는 상태로 몇 시간을 돌게 된다.

### 소스에서

```bash
git clone https://github.com/yuangunn/image-trigger-clicker
cd image-trigger-clicker
python3.12 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
itc doctor
```

요구 사항: macOS, Python 3.11 이상.

## 권장 사용 순서

이 순서를 건너뛰면 대부분 "왜 아무 일도 안 일어나지"에서 막힌다.

| 순서 | 명령 | 목적 |
|---|---|---|
| 1 | `itc init` | 설정 디렉터리와 주석 달린 샘플 설정 생성 |
| 2 | `itc doctor` | 권한·모니터·설정 점검 |
| 3 | `itc record` | **클릭을 녹화해 트리거 이미지와 설정 초안을 한 번에 생성** |
| 4 | 편집 | 초안을 다듬어 `config.toml` 로 옮기기 |
| 5 | `itc test` | 유사도와 후보 수 확인 |
| 6 | `itc run --dry-run` | 클릭 없이 판정 로직만 검증 |
| 7 | `itc run` | 실행 |

3번 대신 하나씩 만들려면 `itc capture <이름>` 으로 영역을 드래그해 저장하고,
클릭 좌표는 `itc pos` 로 읽으면 된다. 손으로 캡처해서 `images/` 에 넣어도 된다.

## 명령어

### `itc run [--profile 이름] [--config 경로] [--dry-run] [--log-file 경로] [--record-dir 디렉터리]`

감시 루프를 돈다. `interval` 초마다 화면을 한 장 찍어 등록된 모든 대상을 검사하고,
매칭되면 `click_delay` 초 뒤에 지정한 좌표를 클릭한다. 클릭 후에는 그 대상의
`cooldown` 초 동안 다시 클릭하지 않는다.

`--dry-run` 은 매칭 판정과 로그는 그대로 하되 실제 클릭만 건너뛴다. 처음 설정한 뒤에는
항상 이걸로 먼저 확인하라.

`--record-dir` 을 주면 **클릭할 때마다 그 순간 화면을 저장한다**(클릭 지점에 빨간 표시).
밤새 돌린 뒤 "정말 맞는 걸 눌렀나"를 눈으로 확인할 수 있다. 무인 실행에서는 켜 두는 편이 좋다.
파일명은 `20260817-195808_대상이름.png` 형태다.

```
[14:03:11] image-trigger-clicker 0.1.0 시작
[14:03:11] 화면: 논리 1512x982 / 물리 3024x1964, 배율 2x
[14:03:11] 프로파일 'sample' — 주기 2초, 임계값 0.85, 클릭 지연 0.3초
[14:03:11] 감시 영역: 전체 화면
[14:03:11] 감시 대상 1개:
[14:03:11]   1. '확인 팝업' ← popup.png | 클릭 offset(dx=+0, dy=+40) | 쿨다운 5초
[14:03:11] 긴급 정지: 마우스를 화면 왼쪽 위 모서리로 (FailSafe) 또는 Ctrl+C
[14:03:29] 매칭: '확인 팝업' 이미지 중앙 x=756 y=520 → 0.3초 후 offset(dx=+0, dy=+40)
[14:03:29] 클릭: '확인 팝업' x=756 y=560
[14:05:11] 생존 확인 — 누적 검사 60회, 클릭 1회
```

### `itc pos`

마우스 좌표를 0.1초 간격으로 한 줄에 갱신 출력한다. `Ctrl`+`C` 로 종료.
`abs` 모드에 넣을 좌표를 여기서 읽는다. 출력되는 값은 **논리 좌표**이고,
설정 파일에 적는 좌표(그리고 `region`)도 전부 같은 논리 좌표다.

### `itc test [--profile 이름]`

현재 화면에서 프로파일의 각 이미지가 잡히는지 1회 검사한다. **클릭하지 않는다.**
실제 유사도(0~1)와, 같은 임계값에서 몇 곳이 매칭되는지를 알려준다.

```
✅ '확인 팝업'  /Users/me/.config/image-trigger-clicker/images/popup.png
     유사도 0.973  (설정값 0.85 → 현재 설정으로 잡힙니다)
     이미지 중앙 x=756 y=520 → 클릭 지점 x=756 y=560 [offset]
```

유사도가 설정값보다 낮으면 `confidence` 를 얼마로 낮추라고 알려준다.
0.70 미만이면 사실상 못 찾은 것으로 본다.

**같은 이미지가 여러 곳에서 매칭되면 경고한다.** 이게 이 명령의 진짜 값어치다.

```
✅ '확인 팝업'  images/popup.png
     유사도 1.000  (설정값 0.9 → 현재 설정으로 잡힙니다)
     이미지 중앙 x=75 y=14 → 클릭 지점 x=75 y=14 [center]
     ⚠️  같은 임계값에서 20곳 이상이 매칭됩니다 (가장 닮은 곳을 고르지만 순위가 뒤집힐 수 있음)
         특징이 뚜렷한 부분으로 다시 자르거나, 임계값을 올리거나, region 으로 좁히세요
```

이 도구는 임계값을 넘는 여러 후보 중 **가장 닮은 곳**을 고른다. 그래도 후보가 여럿이면
위험하다 — 화면이 조금만 바뀌어도 순위가 뒤집혀 다른 곳을 누르게 되고, 로그에는
여전히 "매칭 성공"으로 남는다. 단색 배경이나 균일한 여백처럼 특징이 흐릿한 영역을
잘라 쓰면 이런 일이 난다. 경고가 뜨면 이미지를 다시 자르는 게 정답이다.

### `itc capture <이름>`

**영역을 드래그해서 트리거 이미지를 만든다.** 화면이 캡처 모드로 바뀌면 원하는 부분을
드래그하면 되고, `Esc` 로 취소된다.

```bash
itc capture 확인팝업
```

저장(`images/확인팝업.png`)한 뒤 곧바로 그 이미지가 **지금 화면에서 유일한지** 검사하고,
설정에 붙여넣을 스니펫까지 출력한다.

```
저장: ~/.config/image-trigger-clicker/images/확인팝업.png  (400x200 물리 픽셀)

현재 화면에서 유사도 1.000, 중앙 x=100 y=50
  후보 1곳 — 임계값 0.9에서 유일합니다. 좋은 트리거입니다.

설정에 붙여넣으세요:

[[profiles.sample.targets]]
name     = "확인팝업"
image    = "images/확인팝업.png"
click    = { mode = "center" }
cooldown = 5.0
```

기본 `click` 은 `center` 다. 누를 곳이 이미지 중앙이 아니면 `offset` 이나 `abs` 로 바꾼다.

### `itc record`

**클릭을 녹화해서 설정 초안을 통째로 만든다.** 설정을 손으로 쓰지 않는 가장 빠른 길이다.

```bash
itc record
```

녹화가 시작되면 대상 창에서 평소처럼 클릭하면 된다. 클릭은 그대로 대상 앱에 전달되므로
작업 흐름이 끊기지 않는다. 클릭할 때마다 **그 직전 화면**에서 클릭 지점 주위를 잘라
트리거 이미지 후보로 저장한다. `Ctrl`+`C` 로 끝내면 파일과 설정 초안을 쓴다.

```
[19:58:55] 기록 1: x=400 y=700 → recorded-1.png (320x96)
[19:58:55] 기록 2: x=900 y=400 → recorded-2.png (320x96)
[19:58:56] 클릭 2건 기록 — 트리거 유일성 검사 중
[19:58:56] [경고] 'recorded-1' 는 지금 화면에서 20곳과 닮았습니다 — 다시 자르는 게 좋습니다
[19:58:56] 설정 초안: ~/.config/image-trigger-clicker/config.recorded.toml
```

만들어지는 것:

| 위치 | 내용 |
|---|---|
| `images/<접두어>-N.png` | 클릭 주위를 잘라낸 트리거 후보 |
| `frames/<접두어>-N.png` | 그때의 **전체 화면 원본** |
| `config.recorded.toml` | 설정 초안 (`config.toml` 은 건드리지 않는다) |

`frames/` 를 남기는 이유는, 녹화가 끝나면 그 화면 상태를 다시 만들기 어렵기 때문이다.
잘라낸 범위가 마음에 안 들면 원본에서 다시 자르면 된다.

옵션:

- `--name 접두어` 파일 이름 접두어 (기본 `recorded`)
- `--size 너비x높이` 클릭 주위를 잘라낼 크기, 논리 좌표 (기본 `160x48`)
- `--confidence 값` 초안에 넣을 임계값 (기본 `0.85`)

> **손쉬운 사용 권한이 필요하다.** 클릭을 감지해야 하기 때문이다. 권한이 없으면
> 무엇을 켜야 하는지 안내하고 종료한다. `itc doctor` 로 미리 확인하라.

### `itc doctor`

실행 전 환경 점검. 문제마다 해결 방법을 함께 출력한다.

- 화면 기록 권한 (스크린샷이 검은 화면인지로 판정)
- 손쉬운 사용 권한
- 모니터 구성(대수·원점·배율)과 가상 데스크톱 크기
- 설정 파일 유효성
- 트리거 이미지 파일 존재 여부
- `abs` 모드를 쓰는 대상에 대한 주의 안내

### `itc init [--force]`

`~/.config/image-trigger-clicker/` 와 그 아래 `images/` 를 만들고,
주석이 달린 샘플 `config.toml` 을 생성한다. 기존 파일은 `--force` 없이는 덮어쓰지 않는다.

## 설정 파일

기본 위치는 `~/.config/image-trigger-clicker/config.toml`, `--config` 로 다른 경로를 쓸 수 있다.
트리거 이미지는 `~/.config/image-trigger-clicker/images/` 에 두고 상대 경로로 참조한다
(상대 경로의 기준은 **설정 파일이 있는 디렉터리**). 절대 경로도 쓸 수 있다.

```toml
# 프로파일이 여러 개일 때, --profile 을 생략하면 쓸 기본값
default_profile = "sample"

[profiles.sample]
interval    = 2.0                  # 검사 주기(초)
confidence  = 0.85                 # 매칭 임계값 0.1~1.0
click_delay = 0.3                  # 매칭 후 클릭까지 대기(초)
region      = [0, 0, 1920, 1080]   # 감시 영역 [x, y, 너비, 높이] / 생략하면 전체 화면

[[profiles.sample.targets]]
name     = "확인 팝업"
image    = "images/popup.png"
click    = { mode = "abs", x = 960, y = 640 }
cooldown = 5.0                     # 이 대상을 누른 뒤 재클릭 금지 시간(초)
```

### 프로파일

하나의 설정 파일에 용도별 프로파일을 여러 개 둘 수 있다.

```toml
[profiles.daytime]
interval = 2.0
# ...

[profiles.overnight]
interval = 10.0     # 무인 실행은 주기를 늘려 CPU 부담을 줄인다
# ...
```

```bash
itc run --profile overnight
```

`--profile` 을 생략하면 `default_profile` 을 쓰고, 그것도 없는데 프로파일이 하나뿐이면
그것을 쓴다. 프로파일이 여러 개인데 고르지 않으면 오류를 낸다.

### `click` 지정 방식 3가지

| mode | 필드 | 누르는 곳 |
|---|---|---|
| `abs` | `x`, `y` | 사전 설정된 절대 좌표 (이미지 위치와 무관) |
| `offset` | `dx`, `dy` | 찾은 이미지 중앙에서 상대 이동 |
| `center` | 없음 | 찾은 이미지 중앙 |

```toml
click = { mode = "abs",    x = 960, y = 640 }
click = { mode = "offset", dx = 0,  dy = 40 }
click = { mode = "center" }
```

### 설정 오류

파싱에 실패하면 어느 필드가 왜 잘못됐는지 알려주고 종료한다(종료 코드 2).
오타로 조용히 무시되는 항목이 없도록, 모르는 키도 오류로 처리한다.

```
$ itc run
[10:02:41] [오류] [profiles.sample]: 알 수 없는 항목 'confidance' (쓸 수 있는 항목: click_delay, confidence, interval, region, targets)
```

## ⚠️ macOS 권한 — 안 하면 아무것도 동작하지 않는다

**시스템 설정 → 개인정보 보호 및 보안** 에서 두 가지를 허용해야 한다.

1. **화면 기록** — 없으면 스크린샷이 **검은 화면**으로 나온다. 오류는 나지 않고,
   그냥 영원히 아무것도 매칭되지 않는다.
2. **손쉬운 사용** — 없으면 클릭 이벤트가 무시될 수 있다. `itc record` 는 클릭을
   감지해야 하므로 이 권한이 **반드시** 필요하다.

### 권한은 `itc` 가 아니라 **터미널 앱**에 부여된다

Homebrew로 설치했더라도 권한 목록에 등록해야 하는 것은 `/opt/homebrew/bin/itc` 가 아니라
**그 명령을 실행한 터미널 앱**(터미널.app, iTerm2, VS Code, Warp 등)이다.

- 터미널 앱을 바꾸면 **새 앱에 대해 다시 허용**해야 한다.
- 권한을 켠 뒤에는 그 앱을 **완전히 종료(Cmd+Q)했다가 다시 열어야** 적용된다.
  창만 닫는 것으로는 부족하다.
- `launchd`, `cron`, 다른 도구 안에서 실행하는 경우 권한 주체는 그 부모 프로세스가 된다.

`itc doctor` 가 이 상태를 판정해준다.

## ⚠️ 매칭이 안 될 때 확인할 것

### 대상 창이 화면에 실제로 보여야 한다

화면에 그려지는 픽셀을 읽는 방식이다. 다음 경우는 전부 인식에 실패한다.

- 다른 창에 **가려져 있음** (일부만 가려도 그 부분은 못 찾는다)
- **최소화**되어 있음
- 다른 **데스크탑(Space)** 이나 전체 화면 앱에 가 있음

대상 창은 보이는 상태로 두고, 그 위에 아무것도 겹치지 않게 하라.

### 노트북 뚜껑을 덮지 마라

외장 모니터 없이 뚜껑을 덮으면(클램셸) 내장 디스플레이가 꺼지고 스크린샷이 검게 나온다.
**뚜껑은 열어둔 채로 화면 밝기만 최저로 내려라.** 화면 보호기와 잠자기도 꺼두는 편이 좋다.

```bash
caffeinate -dims itc run     # 실행 동안 잠자기·디스플레이 꺼짐 방지
```

### 트리거 이미지 자르는 요령

- **항상 똑같이 보이는 부분만** 잘라라. 버튼 테두리, 아이콘, 고정된 라벨 같은 것.
- **매번 바뀌는 텍스트**(남은 시간, 사용자 이름, 진행률, 날짜)가 들어가면 매칭이 깨진다.
- **특징이 뚜렷해야 한다.** 단색 배경이나 완만한 그라데이션처럼 밋밋한 영역을 자르면
  화면 곳곳이 똑같이 매칭된다. 가장 닮은 곳을 고르긴 하지만, 후보들의 점수가 비슷하면
  화면이 조금만 바뀌어도 순위가 뒤집혀 엉뚱한 곳을 누르게 된다.
  테두리·모서리·글자처럼 대비가 있는 부분을 포함시켜라.
- 너무 작으면(20px 미만) 화면의 다른 곳과 우연히 일치할 수 있다. 너무 크면 조금만
  달라져도 못 찾는다. 특징이 뚜렷한 40~200px 정도가 무난하다.
- 캡처는 **`itc capture <이름>`** 이 가장 쉽다. 영역 선택·저장·유일성 검사·설정 스니펫을
  한 번에 해준다. `Cmd`+`Shift`+`4` 로 직접 찍어 `images/` 에 넣어도 된다.
- 어느 쪽이든 `itc test` 로 유사도와 후보 수를 확인하라.

### 디스플레이 배율(레티나)

`screenshot()` 은 물리 픽셀, 클릭은 논리 좌표를 쓴다. 이 도구는 그 배율을 자동으로
환산한다(`itc doctor` 가 감지한 배율을 보여준다). 다만 **디스플레이 해상도를 "기본값"이
아닌 스케일링 값으로 두면** 배율이 정수가 아니게 되어 좌표가 1~2픽셀 흔들릴 수 있다.
매칭이 불안정하면 해상도를 기본값으로 되돌려 보라.

또, 트리거 이미지는 **실제 실행할 그 디스플레이에서** 캡처하라. 외장 모니터에서 자른
이미지는 내장 레티나 화면에서 크기가 달라 매칭되지 않는다.

## ⚠️ 여러 대의 모니터

모니터가 여러 대면 스크린샷은 **전부 이어붙인 한 장**이고, 논리 좌표의 원점은 주
디스플레이가 아니라 가장 왼쪽·위 모서리다. 주 디스플레이 **왼쪽**에 놓인 모니터의
좌표는 음수가 된다(예: `x=-1200`). 설정에 그대로 적으면 된다 — `itc pos` 가 보여주는
값이 곧 그 값이다.

`itc doctor` 가 구성을 보여준다.

```
✅ 디스플레이: 모니터 2대, 가상 데스크톱 논리 3720x1169 원점(-1920,0), 배율 2x
   - 모니터 1: 원점(-1920,0) 1920x1080 배율 1x
   - 모니터 2: 원점(0,0) 1800x1169 배율 2x (주 디스플레이)
```

**한계를 분명히 해둔다.**

- **모니터마다 배율이 다르면 좌표가 어긋날 수 있다.** 레티나(2x) 내장 화면과 일반(1x)
  외장 모니터를 같이 쓰는 흔한 구성이 여기 해당한다. 스크린샷 전체에 단일 배율을
  적용하기 때문이다. `itc doctor` 가 이 경우를 감지해 경고한다.
  → 대상 창을 주 디스플레이에 두거나, `region` 으로 그 모니터 영역만 감시하라.
- **다중 모니터 구성은 실기기 검증을 하지 못했다.** 좌표 계산은 음수 원점을 포함해
  단위 테스트로 검증돼 있지만, 실제 두 대를 붙인 상태에서 확인한 적은 없다.
  쓰신다면 `itc test` 로 좌표가 맞는지 먼저 확인하고, `itc run --dry-run` 을 꼭 거쳐라.

## abs 보다 offset 을 먼저 검토하라

절대 좌표(`abs`)는 창을 조금만 옮겨도 빗나간다. 문제는 **무인 실행 중에는 아무도
알아채지 못한다**는 것이다. 계속 매칭은 되는데 계속 엉뚱한 곳을 누르게 된다.

- 대상이 **화면 정중앙에 고정 출력되는 경우에만** `abs` 를 쓴다 (모달 대화상자 등).
- 그 외에는 `offset` 을 써서 **찾은 이미지를 기준으로** 클릭 지점을 잡아라.
  창이 움직여도 트리거 이미지와 버튼의 상대 위치는 그대로다.
- 트리거 이미지 자체가 누를 대상이면 `center`.

`itc doctor` 는 `abs` 를 쓰는 대상이 있으면 이 점을 알려준다.

## 안전장치

장시간 무인 실행이 전제이므로 다음을 보장한다.

- **FailSafe** — 마우스를 화면 **왼쪽 위 모서리**로 밀면 즉시 정지한다.
  자동화가 통제를 벗어났을 때의 최후 수단이다.
- **화면 범위 검사** — 계산된 클릭 좌표가 화면 밖이면 클릭하지 않고 경고 로그만 남기고
  건너뛴다. 엉뚱한 곳을 누르는 사고를 막는다.
- **죽지 않는 루프** — 이미지를 못 찾는 것은 정상 상황으로 처리하고, 그 밖의 예외는
  로그만 남기고 다음 주기로 넘어간다.
- **깔끔한 종료** — `Ctrl`+`C` 와 FailSafe 모두 누적 통계를 남기고 로그 파일을 닫는다.
- **쿨다운** — 같은 대상을 연속으로 난타하지 않는다.
- **`--dry-run`** — 실제 클릭 없이 판정만 검증한다.
- **최고 점수 매칭** — 임계값을 넘는 후보가 여럿이어도 "위에서 처음 만난 곳"이 아니라
  **가장 닮은 곳**을 고른다. 후보가 여럿이면 `itc test` 와 `itc capture` 가 경고한다.
- **실행 녹화** — `--record-dir` 로 클릭 순간의 화면을 남겨, 무인 실행이 끝난 뒤
  제대로 눌렀는지 눈으로 확인할 수 있다.

## 코드 서명·공증에 대하여

**이 프로젝트는 코드 서명(codesign)과 공증(notarization)을 하지 않는다.**

`itc` 는 `.app` 번들이 아니라 Homebrew로 설치되는 CLI 실행 파일이다. Gatekeeper의
격리(quarantine) 검사는 브라우저 등으로 내려받은 `.app`/`.dmg`/`.pkg` 를 대상으로 하며,
패키지 관리자가 설치한 CLI 도구에는 적용되지 않는다. 따라서 "확인되지 않은 개발자" 경고도
뜨지 않는다.

나중에 이 도구를 GUI 앱(`.app`)으로 배포하게 된다면 그때는 Developer ID 서명과 공증이
**필요하다.** 지금 필요 없다는 것은 CLI 배포 형태에 한정된 이야기다. 혼동하지 말 것.

macOS 권한(화면 기록·손쉬운 사용)은 코드 서명과 별개의 문제다. 서명을 하든 안 하든
[위에서 설명한 권한 설정](#️-macos-권한--안-하면-아무것도-동작하지-않는다)은 반드시 해야 한다.

## 개발

```bash
pip install -e ".[dev]"

ruff check .      # 린트
mypy              # 타입 검사
pytest            # 단위 테스트
```

테스트는 좌표 환산, 설정 파싱, 화면 범위 검사 같은 순수 로직만 다룬다.
GUI에 의존하는 부분은 모킹하며, `pyautogui` 는 지연 임포트라 화면 없는 CI에서도 돈다.

```
src/image_trigger_clicker/
├── cli.py        서브커맨드와 감시 루프
├── config.py     TOML 파싱과 검증
├── matcher.py    화면 캡처, 최고 점수 매칭, 좌표 환산(레티나·다중 모니터)
├── clicker.py    클릭 지점 계산과 범위 검사
├── recorder.py   영역 캡처, 클릭 녹화, 스크린샷 표시
├── doctor.py     환경 점검
└── logging.py    타임스탬프 로그
```

## 배포

### 릴리스

버전은 `src/image_trigger_clicker/__init__.py` 의 `__version__` **한 곳**에만 적혀 있다.
`pyproject.toml` 은 그 값을 읽어가고(`[tool.hatch.version]`), `itc --version` 도 같은 값을
쓰므로 어긋날 수가 없다. 올릴 때 그 한 줄만 고치면 된다.

`v*` 태그를 밀면 GitHub Actions가 sdist/wheel을 빌드해 Release를 만들고 아티팩트를 첨부한다.

```bash
# 1) __version__ 을 0.2.0 으로 고치고 커밋
# 2) 같은 번호로 태그
git tag v0.2.0
git push origin v0.2.0
```

태그 번호와 `__version__` 이 다르면 formula의 `brew test` 가 잡아낸다
(`assert_match "image-trigger-clicker #{version}"`).

같은 태그 푸시로 `update-tap.yml` 도 함께 돌아, 소스 tarball의 SHA256을 계산해
`yuangunn/homebrew-tap` 의 formula 버전과 해시를 자동으로 커밋한다.
이 워크플로는 tap 저장소에 쓰기 권한이 있는 PAT을 `secrets.TAP_GITHUB_TOKEN` 으로 받는다.

> `release: published` 가 아니라 태그 푸시에 거는 이유: GitHub 은 기본 `GITHUB_TOKEN` 이
> 만든 이벤트로 다른 워크플로를 트리거하지 않는다(무한 루프 방지). Release 워크플로가
> `GITHUB_TOKEN` 으로 릴리스를 만들기 때문에, 릴리스 이벤트에 걸어두면 tap 갱신이
> 영원히 실행되지 않는다.

### tap 저장소 준비

`packaging/homebrew-tap/` 아래 내용을 `yuangunn/homebrew-tap` 저장소로 복사한다.
자세한 절차와 `brew update-python-resources` 사용법은
[`packaging/homebrew-tap/README.md`](packaging/homebrew-tap/README.md) 를 보라.
